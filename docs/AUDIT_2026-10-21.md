## Precision finding

The current official CSV preserves OBS_VALUE strings at precision greater than four decimals
(e.g. 2026-10-20 = `0.010133920731271543`) while metadata still reports DECIMALS=4.

This invalidates the earlier implementation assumption that DECIMALS=4 is a hard storage-precision
cap. The corrected ingestion rule is:

1. preserve the official OBS_VALUE decimal string exactly;
2. validate DECIMALS=4 as source metadata;
3. never round or overwrite raw official values;
4. use explicit four-decimal normalization only when comparing the current official vintage with
   the accepted DB31 four-decimal baseline.
